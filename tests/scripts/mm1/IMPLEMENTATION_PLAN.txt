基于对 US-align 源码架构的深入剖析，现撰写一份完整的实施方案。本方案将改动按功能拆分为三个递进阶段（-dir1 → -dir2 → -dir），每阶段包含 5 个细化步骤，确保步步可验证、可回归。

US-align -mm 1 与 -dir/-dir1/-dir2 模式适配方案
一、需求背景与目标
1.1 业务背景
US-align 的 -mm 1 模式（寡聚体/多链复合物比对）和 -dir/-dir1/-dir2 模式（目录批量比对）均是核心功能。然而当前存在两类问题：
- -dir 与 -mm 1 被硬编码互斥（USalign.cpp:3459），无法使用
- -dir1/-dir2 与 -mm 1 虽未被拦截，但 MMalign 会将目录下所有文件合并为一个巨型复合物，产生错误结果

1.2 需求目标
- 实现 -dir1 + -mm 1：目录中每个复合物 vs 指定目标复合物
- 实现 -dir2 + -mm 1：指定查询复合物 vs 目录中每个复合物
- 实现 -dir  + -mm 1：目录下所有复合物的全对全比对（上三角）
- 确保现有单体 -dir、-dirpair、单对比对逻辑不受影响

二、核心痛点与根因分析
MMalign 与 TMalign 的核心差异：

        TMalign                         MMalign
解析    get_PDB_lines（逐文件）         parse_chain_list（合并所有文件）
循环    内部 i/j 双层循环               无循环，全部合并后一次比对
-dir    每个文件单独解析→逐对比对 ✓    所有文件合并→巨型复合物 ✗

parse_chain_list（MMalign.h:1077）的逻辑：
for each file in chain_list:
    解析该文件的所有链 → 逐个追加到 xa_vec/ya_vec
所以传入 [a.pdb, b.pdb, c.pdb] 会得到一个包含三个文件所有链的巨型复合物。

正确做法：在主函数中添加外层循环，每次只传单个文件对给 MMalign。

三种模式的 chain_list 结构与遍历方式：

模式                        chain1_list                              chain2_list                 遍历方式
-dir1 PDB/ list target     [PDB/a.pdb, PDB/b.pdb, PDB/c.pdb]        [target.pdb]                单层循环 chain1_list
query -dir2 PDB/ list      [query.pdb]                              [PDB/a.pdb, PDB/b.pdb, ...] 单层循环 chain2_list
-dir PDB/ list             [PDB/a.pdb, PDB/b.pdb, PDB/c.pdb]        同 chain1_list              上三角二重循环 (ii<jj)

前缀剥离参数对照（MMalign 内部使用 xname.substr(dir1_opt.size()) 剥离）：

模式        xname 示例      yname 示例      传入 dir1_opt    传入 dir2_opt
-dir1       PDB/a.pdb       target.pdb      dir1_opt         ""
-dir2       query.pdb       PDB/a.pdb       ""               dir2_opt
-dir        PDB/a.pdb       PDB/b.pdb       dir_opt          dir_opt

三、开发工作流：Usalign-beta 分阶段交付

整体策略：每完成一种功能的编码适配并编译通过后，暂停并通知开发人员进行手动测试验证。开发人员确认测试通过后，再继续下一功能的适配。以此类推，确保每一步都有人工验证关口。

具体流程：

1. 创建 Usalign-beta 目录
   将 USalign-master 目录下的所有源码文件（.cpp, .h, Makefile 等）复制到 Usalign-beta 目录。
   后续所有代码修改均在 Usalign-beta 目录中进行，保持原 USalign-master 目录不变。

2. 三阶段递进开发
   第一阶段（-dir1 + -mm 1）：
     a. 编码完成 → 编译通过 → 通知开发人员手动测试
     b. 开发人员按验证矩阵（步骤 1.5）执行手动测试
     c. 测试通过 → 将本次修改提交到 Usalign-beta → 进入第二阶段

   第二阶段（-dir2 + -mm 1）：
     a. 编码完成 → 编译通过 → 通知开发人员手动测试
     b. 开发人员按验证矩阵（步骤 2.5）执行手动测试（含 -dir1 回归）
     c. 测试通过 → 将本次修改提交到 Usalign-beta → 进入第三阶段

   第三阶段（-dir + -mm 1）：
     a. 编码完成 → 编译通过 → 通知开发人员手动测试
     b. 开发人员按验证矩阵（步骤 3.5）执行手动测试（含 -dir1/-dir2 回归）
     c. 测试通过 → 将本次修改提交到 Usalign-beta → 全部功能适配完成

3. 每阶段交付物
   - 修改后的源代码（在 Usalign-beta 目录中）
   - 编译通过的可执行文件 USalign（或 USalign.exe）
   - 当前阶段的验证矩阵，供开发人员逐项核对

七、已知限制

1. 错误处理：MMalign 内部使用 PrintErrorAndQuit（exit(1)），单个损坏文件会终止整个批量任务。
   本次不改动 MMalign 内部错误处理（影响面太大）。用户应确保目录中文件格式正确。

2. 性能：无文件解析缓存，每个文件在每对比对中都被重新解析。对小目录（N<30）影响可忽略。

3. -full 选项：在目录模式下会产生极其冗长的输出（每对 × 每条链的详细比对），不建议组合使用。
