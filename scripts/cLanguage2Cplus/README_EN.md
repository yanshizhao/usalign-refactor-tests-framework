# cLanguage2Cplus — USalign C→C++ Refactoring Regression & Performance Test Framework

## 1. Overview

This directory contains the regression and performance test framework for **USalign**, a general-purpose protein/nucleic acid structure alignment tool implemented as a header-only C++ codebase with the main entry point at `../../../USalign/USalign.cpp` (~3600 lines).

> **Directory layout requirement**: `usalign-refactor-tests-framework/` must be placed in the same parent directory as the `USalign/` source directory. All relative paths in scripts (`../../../USalign/`) depend on this layout.

The primary purpose of this framework is to verify that the C→C++ style refactoring of the USalign source code **introduces no functional regressions or performance degradation**. The refactoring covers 22 categories of C-style → C++ style mappings, spanning all 27 source files (15 `.h` + 12 `.cpp`), totaling 51 commits.

## 3. Quick Start

**Prerequisites**:
- GCC (`g++`) capable of compiling USalign: requires `-O3 -ffast-math`
- Python 3.6+
- All `.py` scripts in this directory **must be run from within this directory**

### 3.1 Establish Baseline (run once before modifying source code)

```bash
cd cLanguage2Cplus

# 1. Generate functional baseline — compile USalign from master, run 14 cases, save to baseline/
python create_baseline.py

# 2. Generate performance baseline — compile USalign from master, 4 cases × 5 runs each, save to perf_baseline/baseline.csv
python create_perf_baseline.py
```

### 3.2 Development Iteration (run after each source modification)

```bash
cd cLanguage2Cplus

# 1. Run functional regression — compile from USalign-beta, byte-level comparison of 14 cases
python run_regression.py

# 2. Run performance regression — compile from USalign-beta, 5-run average, compare against baseline
python run_perf_test.py
```

### 3.3 Build Test Database (optional)

```bash
# Requires I-TASSER PDB template library. Modify SOURCE_DIR in build_Small_DB.py first
python build_Small_DB.py
```

## 4. Script Details

### 4.1 `create_baseline.py` — Functional Baseline Generator

| Item | Description |
|------|-------------|
| **Purpose** | Generate gold-standard output for regression testing |
| **Compile source** | `../../../USalign/USalign.cpp` from `master` branch |
| **Output** | `USalign_orig.exe` + `baseline/` directory (14 `.out` + `sup.pdb`) |
| **Input** | `testcases_functional.txt` |
| **When to run** | **Once** before modifying source code |
| **How it works** | Auto checkout → `master`, compile original, run 14 cases sequentially, capture stdout+stderr, clean via `clean_slash()` and save to `baseline/` |

### 4.2 `run_regression.py` — Functional Regression Runner

| Item | Description |
|------|-------------|
| **Purpose** | Verify modified output is byte-identical to baseline |
| **Compile source** | `../../../USalign/USalign.cpp` from `USalign-beta` branch |
| **Output** | `USalign_mod_<pid>.exe` + `current/` (14 `_mod.out`) + `diffs/` (diff files) |
| **Input** | `testcases_functional.txt` + `baseline/` |
| **When to run** | After each source modification |
| **Result classification** | `PASS` = identical / `WARNING` = CPU time only / `FAIL` = business data mismatch (generates `.diff`) |
| **Special handling** | `superposed_structure` additionally compares `sup.pdb`; auto-cleans `.pml` files; `clean_slash()` cleans `/` prefix in `Name of Structure_X:` lines |
| **Note** | Clears `current/` and `diffs/` before each run |

### 4.3 `create_perf_baseline.py` — Performance Baseline Generator

| Item | Description |
|------|-------------|
| **Purpose** | Generate performance reference baseline |
| **Compile source** | `master` branch |
| **Output** | `USalign_orig.exe` + `perf_baseline/baseline.csv` |
| **Input** | `testcases_performance.txt` |
| **Parameters** | Each case run **5 times**, average of `#Total CPU time` |
| **When to run** | Once before modifying source code |

### 4.4 `run_perf_test.py` — Performance Regression Runner

| Item | Description |
|------|-------------|
| **Purpose** | Detect performance degradation introduced by modifications |
| **Compile source** | `USalign-beta` branch |
| **Output** | `USalign_mod_<pid>.exe` + `perf_current/performance.csv` |
| **Input** | `testcases_performance.txt` + `perf_baseline/baseline.csv` |
| **Parameters** | Each case run **5 times**, average taken |
| **Thresholds** | `<20%` → PASS / `20%-50%` → WARNING / `>50%` → FAIL |
| **Formula** | `pct = (T_current - T_baseline) / T_baseline * 100` |

### 4.5 `build_Small_DB.py` — Database Builder

| Item | Description |
|------|-------------|
| **Purpose** | Randomly sample 100 structures from I-TASSER PDB library to build `data/smallDB/` |
| **Output** | `data/smallDB/` directory (100 `.pdb` + `list.txt`) |
| **Configuration** | Modify `SOURCE_DIR` in script to actual PDB directory path |
| **Fixed seed** | `random.seed(42)` for reproducibility |

### 4.6 Standalone Program Test Scripts

Each standalone program (`standalone/<program>/`) has two core scripts:

**`create_baseline.py`**: Extract standalone `.cpp` source from `master` branch → compile → run cases → save baseline output to `baseline/`

**`run_test.py`**: Switch to `USalign-beta` → compile standalone program → run cases → byte-level comparison against baseline. Filters `#Total CPU time` lines via `strip_cpu_time()` before comparison (CPU time fluctuation is not a regression criterion).

## 6. How It Works

### 6.1 Dual-Executable Comparison Model

```
┌──────────────┐       ┌──────────────┐
│ USalign_orig │       │ USalign_mod  │
│ (master      │       │ (USalign-beta│
│  compiled)   │       │  compiled)   │
└──────┬───────┘       └──────┬───────┘
       │ output                │ output
       ▼                       ▼
  baseline/               current/
  (gold standard)         (modified version)
       │                       │
       └───── byte-level ──────┘
               │
       PASS / WARNING / FAIL
```

Both executables are compiled from `../../../USalign/USalign.cpp`; the difference is the Git branch used:
- **Original** = compiled from `master` branch (clean pre-refactoring code)
- **Modified** = compiled from `USalign-beta` branch (code with all C→C++ refactoring)

### 6.2 Output Comparison Logic

`run_regression.py` performs **byte-level comparison**:

1. Capture USalign `stdout + stderr`, apply `clean_slash()` to remove redundant `/` prefix in `Name of Structure_X:` lines (a known quirk of USalign output)
2. Strip `#Total CPU time` lines via `strip_cpu_time()`
3. Compare stripped output: identical → PASS; CPU time only diffs → WARNING; business data diffs → FAIL
4. When inconsistent, generates unified diff in `diffs/<case_name>.diff`

### 6.3 Key Conventions

- Baseline output files are named `<case_name>.out`; modified version appends `_mod` suffix (e.g. `standard_protein_mod.out`)
- `superposed_structure` additionally compares the generated `sup.pdb` structure file
- `current/`, `diffs/`, `perf_current/` are cleared and rebuilt on each run — **do not store important files there**
- On Windows, `-dir` / `-dir2` use backslash path separators (`.\`)
- The original Git branch is automatically restored after test completion

## 7. Dependencies & Compilation

| Item | Description |
|------|-------------|
| Compiler | `g++`, requires `-O3 -ffast-math -lm` (Windows may need `-static`) |
| Python | 3.6+, standard library only (`subprocess`, `difflib`, `csv`, `pathlib`, `shutil`, `re`) |
| USalign source | `../../../USalign/USalign.cpp` (main entry) and all `.h` headers |
| Git branches | `master` (original baseline) + `USalign-beta` (modified, 51 commits ahead of master) |

### 7.1 Multi-Threading Support

The main USalign program supports OpenMP parallel acceleration:

- **Compile time**: Add `-fopenmp` flag (automatically included by `make`)
- **Runtime**: Use `-threads N` to specify thread count, e.g., `-threads 4`

Batch modes supporting `-threads`: `-dir`, `-dir1`, `-dir2`, `-dirpair`

> **Note**: Standalone programs (TMscore, HwRMSD, MMalign, pdb2ss) **do not** support multi-threading. Neither `-fopenmp` nor `-threads` is needed for them.

## 9. Known Limitations

1. Windows native compilation does not support `.gz`/`.bz2` compressed files (`pstream.h` depends on POSIX pipes)
2. Performance tests may fluctuate due to system load; `20%-50%` WARNING requires manual assessment
3. Standalone program tests (TMscore/HwRMSD/MMalign/pdb2ss) are not covered by `run_regression.py`; run `standalone/<program>/run_test.py` separately
4. When remote repository is disconnected, `USalign-beta` branch may not be pushable (currently resolved, 51 commits pushed to origin)
