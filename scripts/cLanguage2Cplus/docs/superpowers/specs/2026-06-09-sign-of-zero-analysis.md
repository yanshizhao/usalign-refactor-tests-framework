# 符号零（-0.0000000000 vs 0.0000000000）问题分析报告

**日期**: 2026-06-09
**背景**: USalign-beta 分支重构后回归测试 3 个已知 FAIL（all_vs_all、msta_rna、database_search）
**问题现象**: 旋转矩阵输出中 `-0.0000000000` 与 `0.0000000000` 在 baseline 和修改版之间翻转

---

## 一、问题现象

### 1.1 差异实例（取自 all_vs_all.diff）

```
------ The rotation matrix to rotate Structure_1 to Structure_2 ------
m               t[m]        u[m][0]        u[m][1]        u[m][2]
-0       0.0000000000   1.0000000000   0.0000000000  -0.0000000000
-1      -0.0000000000  -0.0000000000   1.0000000000   0.0000000000
-2      -0.0000000000   0.0000000000  -0.0000000000   1.0000000000
+0      -0.0000000000   1.0000000000  -0.0000000000   0.0000000000
+1      -0.0000000000   0.0000000000   1.0000000000   0.0000000000
+2      -0.0000000000  -0.0000000000  -0.0000000000   1.0000000000
```

`-` 行 = baseline（master），`+` 行 = 修改版（USalign-beta）。
差异仅在于数值 `±0.0000000000` 的符号位——非零数值完全相同。

### 1.2 三类差异

| 差异类型 | 示例 | 出现位置 | 影响 |
|:---------|:-----|:---------|:-----|
| **符号零翻转** | `-0.0000000000` ↔ `0.0000000000` | 旋转矩阵 off-diagonal + t | 仅显示，无实际影响 |
| **最后一位 ±1** | `193.6890484356` ↔ `193.6890484355` | 旋转矩阵 t 值 | ~10⁻¹⁰ 级差异 |
| **链配对选择** | `US735192405.pdb:A` ↔ `US7351924051.pdb:A` | MSTA 多链比对 | TM-score 极接近时的次优配对 |

本报告专注于第一类（符号零翻转），这是用户最直观看到的问题。

---

## 二、诊断方法与过程

### 2.1 第一步：确认 Kabsch 输出的是真实 `±0.0` 还是极小非零值

在 `output_rotation_matrix` 函数入口处添加 IEEE 754 hexfloat 输出：

```cpp
cerr << hexfloat;
for (int k = 0; k < 3; k++)
    cerr << "t[" << k << "]=" << t[k]
         << " u[" << k << "][0]=" << u[k][0]
         << " u[" << k << "][1]=" << u[k][1]
         << " u[" << k << "][2]=" << u[k][2] << endl;
cerr << defaultfloat;
```

**结果（identity 旋转矩阵，即相同结构比对）：**

```
t[0]=-0x1.c8f4eee7ccd77p-44  u[0][0]=0x1.fffffffffffffp-1  u[0][1]=-0x1p-52  u[0][2]=0x1.2p-50
t[1]=-0x1.8p-47              u[1][0]=0x1p-55             u[1][1]=0x1.0000000000001p+0  u[1][2]=0x1.8p-53
t[2]=-0x1.3b67ab3ce58bp-44   u[2][0]=-0x1.88p-50         u[2][1]=-0x1p-52  u[2][2]=0x1.0000000000001p+0
```

**关键发现：**
- `u[0][1] = -0x1p-52 ≈ -2.22e-16` — 不是精确 0，是极小非零值
- `u[1][2] = 0x1.8p-53 ≈ +1.67e-16` — 正值极小非零值
- **所有 off-diagonal 都是 10⁻¹⁶ ~ 10⁻¹³ 级的非零值**，只是被 `%.10f` 舍入到 10 位小数后显示为 `0.0000000000`

### 2.2 第二步：确认 `%a` 与 `%.10f` 的映射关系

编写最小验证程序：

```c
double pos = +7.98e-17;   // 类似 baseline 的 u[0][1]
double neg = -2.41e-16;   // 类似 修改版的 u[0][1]

printf("%%a       = %a\n", pos);   // 0x1.7p-54
printf("%%.10f    = %.10f\n", pos); //  0.0000000000
printf("%%a       = %a\n", neg);   // -0x1.14p-52
printf("%%.10f    = %.10f\n", neg); // -0.0000000000
```

**结论：** `%.10f` 对 `-7.98e-17` 的输出是 `-0.0000000000`。这不是"负零"概念上的负零——而是 IEEE 754 格式标准对**负数舍入到 0 时保留符号位**的必然结果。

### 2.3 第三步：在 Kabsch 计算入口处对比 master 和 beta 的 a/b 矩阵

在 `u[i][j] = b[i][0]*a[j][0] + b[i][1]*a[j][1] + b[i][2]*a[j][2]` 之前插入 hexfloat 输出：

```cpp
fprintf(stderr, "Kabsch_diag a=");
for (int _i=0;_i<3;_i++) for (int _j=0;_j<3;_j++) fprintf(stderr, "%a ", a[_i][_j]);
fprintf(stderr, "b=");
for (int _i=0;_i<3;_i++) for (int _j=0;_j<3;_j++) fprintf(stderr, "%a ", b[_i][_j]);
```

**在 master 分支和 USalign-beta 分支分别编译运行同一测试用例（all_vs_all），逐比特对比 a 矩阵：**

| a[0][0] | a[0][1] | a[0][2] |
|:--------|:--------|:--------|
| master: `0x1.d0b67eb49d**969**p-1` | master: `0x1.ac118bd869a**ec**p-2` | master: `-0x1.35f430147**6de4**p-5` |
| beta:   `0x1.d0b67eb49d**95a**p-1` | beta:   `0x1.ac118bd869a**f4**p-2` | beta:   `-0x1.35f430147**8128**p-5` |
| 差: **15 ULP** | 差: **8 ULP** | 差: **4652 ULP** |

**a 矩阵的每一个值在 master 和 beta 之间都不同**（最后几位比特），差异从几个到几千个 ULP。

### 2.4 第四步：追踪 u[0][1] 的具体计算过程

u[0][1] = b[0][0]×a[1][0] + b[0][1]×a[1][1] + b[0][2]×a[1][2]

三个乘积项的实际数值：

| 项 | master | beta | 差异(ULP) |
|:---|:-------|:-----|:----------|
| b[0][0]×a[1][0] | **+0.25998261606892165** | **+0.25998261606892109** | 10 |
| b[0][1]×a[1][1] | **-0.23032561709102511** | **-0.23032561709099558** | 1064 |
| b[0][2]×a[1][2] | **-0.029656998977896452** | **-0.029656998977925748** | 8444 |
| **总和** | **+7.98e-17** | **-2.39e-16** | — |

**关键洞察：** 三个乘积项每个都在 **0.03~0.26** 之间，远不是小量。它们几乎精确抵消，残差只有 **10⁻¹⁶** 级。master 版残差为 **正（+7.98e-17）**，beta 版残差为 **负（-2.39e-16）**。符号翻转是因为三个大数的最后几位 ULPs 不同，抵消平衡点在 10⁻¹⁶ 级被打破。

### 2.5 第五步：追溯差异的根本来源

a 和 b 矩阵来自 Kabsch SVD 的前半部分（协方差矩阵 r → SVD 分解 → 特征向量）。SVD 是一个约 300 行的迭代数值算法，包含大量浮点运算。

**差异传播链：**

```
重构改变内存布局 (double** → CoordArray/Vec3/RotMat)
  → 编译器对不同内存布局生成不同机器指令
  → 指令调度和寄存器分配改变
  → 相同的算术表达式产生不同的中间舍入
  → SVD 迭代将每次舍入差异逐级放大（每次迭代 ~30 次浮点运算 × ~50 次迭代）
  → a 和 b 矩阵每个值在最后几位比特不一致
  → u = b × a^T 的 off-diagonal 是三个 ~0.1 级大数的抵消和
  → a/b 的最后几位异导致抵消平衡点位移
  → off-diagonal 残差从正变成负（或负变成正）
  → %.10f 格式化后显示为 -0.0000000000 或 0.0000000000
```

## 三、关于"截断到 10 位精度"的不可行性验证

用户提出的假设：如果将中间计算值都保留到 10 位精度，是否可以消除此误差？

验证程序：

```c
a[1][0] 精确值 = 0x1.254fd1b9f2464p-2  = 0.28643729875017798
a[1][0] 截断   = 0.2599826161           = 0.2599826161
误差           = 0.02645468265          ≈ 2.6×10⁻²

乘积误差 = 精确乘积 - 截断乘积 = 0.25998261606892165 - 0.23615923357935134
         = 0.0238233824895703     ≈ 2.4×10⁻²
```

截断导致 **~10⁻² 级的误差**，比 Kabsch 的 **~10⁻¹⁶ 残差** 大了 **10¹⁴ 倍（100 万亿倍）**。如果真截断到 10 位精度，Kabsch SVD 将无法收敛，TM-score 从 0.81 变成完全错误的值。

**结论：该方法不可行。**

---

## 四、解决方案

### 4.1 方案：在 `output_rotation_matrix` 中归一化极小值

在输出格式化之前，将绝对值小于显示阈值（1e-11）的值强制设为 `+0.0`：

```cpp
auto clean = [](double x) { return (std::abs(x) < 1e-11) ? +0.0 : x; };
ss << strfmt("%d %18.10f %14.10f %14.10f %14.10f\n",
    k, clean(t[k]), clean(u[k][0]), clean(u[k][1]), clean(u[k][2]));
```

**为什么阈值取 1e-11：**

| 来源 | 最大残差量级 | 需保留的最小非零值 |
|:-----|:------------|:-----------------|
| u off-diagonal | ~10⁻¹⁵ | 旋转矩阵分量 ~10⁻¹ |
| t 平移向量 | ~10⁻¹³ | 平移量 ~10⁰ |
| **阈值 10⁻¹¹** | 完全覆盖残差 | 不影响任何实际值 |

阈值 1e-11 比最大残差（~10⁻¹³）大 100 倍，比旋转矩阵最小有意义分量（~10⁻¹）小 10¹⁰ 倍——**安全余量极大**。

### 4.2 为什么安全

- `output_rotation_matrix` 是 `const Vec3& t, const RotMat& u` —— 不修改原始值
- 所有调用点都在计算完成后（`output_results`、`output_mTMalign_results`、`output_TMscore_results`）
- 不影响任何计算流程（Kabsch、TM-score、superposition）

### 4.3 方案效果预期

修改后：
- `-0.0000000000` → ` 0.0000000000`（符号零翻转消失）
- 最后一位 ±1 的差异（如 `193.6890484356` vs `193.6890484355`）保持不变——它们是正常浮点差异，不在本方案的修正范围内
- 链配对选择差异不变——这是 TM-score 极接近时的算法级次优选择

### 4.4 已知局限

关闭 `-ffast-math` 编译选项可以**完全消除**所有 3 个 FAIL（包括最后一位 ±1 和链配对选择）。本方案只处理了符号零翻转这一项（最影响视觉的差异）。完消除有 3 个 FAIL 需要更新 baseline 或者关闭 `-ffast-math`。

---

## 五、关键结论

1. **不是 bug。** 这是 IEEE 754 浮点算术的固有属性——数值计算中 10⁻¹⁶ 级的残差在 `%.10f` 格式化时的符号位展示问题。

2. **两种版本在数学上等价。** master 和 beta 的 Kabsch 计算路径不同（不同内存布局 → 不同指令生成 → 不同舍入方向），但残差都在 10⁻¹⁶ ~ 10⁻¹³ 量级，完全不影响 TM-score、RMSD 等业务指标的精度。

3. **方案修复是纯显示层修正。** `output_rotation_matrix` 中的 `clean` lambda 不影响任何计算，只改变 `%.10f` 的输出在阈值以下的符号表现。
